# Changelog

What changed in each cadaclysm release, for the developers building on the SDK: the
readers, the mesher, the blacksmith kernel, the C API and the wrappers. The newest
release is first; each GitHub release page opens with its own section.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the
versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) (0.x: a
minor release may change the API).

## [Unreleased]

## [0.14.2] - 2026-11-13

### Added

- Holes, ribs and webs, and patterns, in the kernel, the C ABI (`cadaclysm_blacksmith_hole`, `_hole_tool`, `_rib`, `_rib_tool`, `_web`, `_web_tool`, `_pattern`, `_pattern_feature`, `_pattern_rectangular`, `_pattern_circular`, `_pattern_along`, with `CADACLYSM_BLACKSMITH_HOLE_*`, `_FEATURE_*`, `_RIB_*`, `_WEB_*` and `_ORIENT_*` codes), the web build, Python and every wrapper: C#, Go, Java, Node (native and wasm), Rust (and its web build), Swift, LuaJIT, Godot and C++. `web`'s `both_ways` defaults to false. `Solid.hole(points, diameter, ...)` drills one hole spec at one point or many -- through, blind with a drill point of any included angle (or flat), to a face, or to next (until the bore first leaves the material), along a direction or each point's face normal, with a counterbore or countersink head -- the bore, heads and point exact cylinders and cones, and a `HoleReport` of the holes, where each bore ends and the faces added. `Solid.rib(curve, plane, thickness, ...)` fills the region between an open curve in a plane and the body, the curve's ends carried to the body, thick to both sides, the front or the back; `Solid.web(curves, plane, thickness, ...)` offsets each curve in the plane and runs its walls to the body or a depth, many curves (a network where they cross) in one join. `Pattern.rectangular`, `circular` and `along` build placements -- lists of rigid transforms, instance 0 the original, symmetric or not, with suppressed instances -- and `Solid.pattern` patterns a body (copies apart put together with no boolean at all) while `Solid.pattern_feature` cuts or joins any closed tool at every placement, beside a `PatternReport`. Copies apart from each other are one multi-lump tool and **one** boolean however many there are, so a 4 x 3 pattern of holes is one cut, and `hole` at many points the same. Each verb has a `_tool` sibling returning the tool body alone. Angles are radians. Refused by name: a diameter or thickness not positive, a depth or face the extent does not take, a head not wider than the bore, an angle out of range, a point not on a face with no direction, a hole that removes nothing, a curve closed or not in its plane, a rib or web that meets nothing or is not closed by the body, a count of 0, a zero direction or axis, a skip past the count, a transform that is not rigid, and a tool that is not closed. A revolved rib (OCCT's `MakeRevolutionForm`) is not built: its join leaves free edges.
- Hidden-line drawings of solids: `Solid.hlr` (the C ABI's `cadaclysm_blacksmith_hlr` with its line, Bézier, report and free calls, the kernel wasm module, Python and every wrapper) projects one or several solids from a direction or an eye and gives every line of the view -- sharp edges, smooth (tangent) edges, outlines where a surface turns away, isocurves, open-sheet rims -- each marked visible or hidden, as exact rational Béziers on the page and in space. One solid hides another. Triangle meshes too (`hlr_mesh`, feature edges by angle). The SVG writer drops hidden lines or draws them dashed (`SVG_HIDDEN_REMOVED`, `SVG_HIDDEN_DASHED`). `projected_outline` gives the boundary of the solids' shadow on the view plane as profiles, holes included.
- 2D drawings as DXF and SVG: a `Page` takes hidden-line views at a scale, profiles, hatches (solid, ANSI31, ANSI37, steel) and text, on layers with their line types, and writes SVG or DXF (R2000, the same bytes every run). `dxf_profiles` reads a DXF file's lines, arcs, circles, ellipses, polylines and splines (blocks inserted) back as closed profiles. In Rust, a building sheet's paper drawing converts into the same drawing (`cadaclysm_bim::paper::drawing`) and so writes DXF.
- Where a body passes through itself, in the Rust kernel: `cadaclysm_blacksmith::self_intersections` (and `_with`, reporting progress) gives the same chains and overlaps as `intersect_bodies` -- two of its faces crossing, with the exact curve where the face-pair engine gives one; a face folding through itself, found on the mesh; a face doubled on another -- and never its own edges and vertices, however the file shares them. Found on the mesh first, so a crossing narrower than the mesh tolerance can be missed. In the C ABI as `cadaclysm_blacksmith_self_intersect` (the same intersection handle `cadaclysm_blacksmith_intersect` returns, read and freed the same way), in the kernel wasm module, and in every wrapper as `Solid.self_intersections(tolerance)` (`SelfIntersections` in C# and Go, `selfIntersections` in Java, Node and Swift; Python, Node, C++ and LuaJIT also take a progress callback).
- Whether bodies are fit to be a verb's arguments, before the verb refuses them: `Solid.check(other, operation, tolerance)` (the kernel's `check_arguments`, the C ABI's `cadaclysm_blacksmith_check` with `_check_count`, `_check_finding` and `_check_free`, the kernel wasm module, and every wrapper) gives a list of findings, each a kind, the argument it is on, up to two indices and a size. Every argument is checked for no faces, features below the tolerance and loose edges (as `health` finds them) and where it passes through itself (as `self_intersections` finds it); an operation -- `join`, `cut`, `common`, `split_sheet`, `trim`, `merge` or `intersect` -- adds what that verb refuses an argument for: an open operand (one finding per free edge), a merge's region wall, a merge's non-analytic face. An empty list is a valid pair. OCCT's curve-on-surface and continuity checks are not among them.
- HUD overlays: profiles, text and images drawn in window space at one of nine anchors, kept in place as the window resizes, moved cheaply and pickable, in every view wrapper and the web View (View 1.24).
- Frame statistics: frames drawn, CPU and GPU frame time, triangles and draw calls of the last frame, for an FPS counter that stays right while the scene is still, in every view wrapper and the web View (View 1.25).
- Edge, curve and isocurve colours, view-wide and per item, in every wrapper (View 1.23): every edge, curve or isocurve in one colour or in each part's own, and an item's own edges, curves or isocurves in a colour over that -- over its colour and a kernel solid's edge paint too, on the exact edges, the levels of detail and after an upload -- cleared back to the view's with none. C `cadaclysm_view_set_line_colour`, `cadaclysm_view_line_colour` and `cadaclysm_view_set_item_line_colour` on `CADACLYSM_VIEW_LAYER_EDGES`, `_CURVES` or `_ISOCURVES`; Rust `View::set_line_colour`, `View::line_colour`, `View::set_item_line_colour` on a `Layer`; Python `View.set_edge_colour`, `View.edge_colour`, `View.set_item_edge_colour`; C# `View.EdgeColour("#202020", fromPart: false)`, `View.EdgeColour()` (a `LineColour`), `Item.EdgeColour("#ff0000")` (null clears); C++ `View::set_edge_colour`, `View::edge_colour`, `Item::set_edge_colour`; Java `View.setEdgeColour`, `View.edgeColour`, `Item.setEdgeColour`; Go `View.SetEdgeColour`, `View.EdgeColour`, `Item.SetEdgeColour`; Swift `View.setEdgeColour`, `View.edgeColour`, `Item.setEdgeColour`; Node `View.setEdgeColour`, `View.edgeColour`, `Item.setEdgeColour`; LuaJIT `View:set_edge_colour`, `View:edge_colour`, `Item:set_edge_colour`; the Rust SDK `View::set_edge_colour`, `View::edge_colour`, `Item::set_edge_colour` (in the browser too); the web View `setEdgeColour`, `edgeColour`, `setItemEdgeColour` -- and the same for curves and isocurves in each. Every colour argument takes colour text. The terminal draws them; the render-view library keeps the view-wide colours and refuses an item's.
- User layers in every view wrapper (View 1.16, until now Python's and the web View's): an item on one of 32 layers, a layer switched off and on in every viewport, and a viewport drawing only the layers in its mask, every layer by default. C++ `Item::user_layer`, `View::user_layer`, `Viewport::layer_mask`; C# `Item.UserLayer`, `View.UserLayer`, `Viewport.LayerMask`; Java `Item.userLayer`, `View.userLayer`, `Viewport.layerMask`; Go `Item.UserLayer`, `View.UserLayer`, `Viewport.LayerMask` (0, the zero value, is every layer); Swift `Item.userLayer`, `View.userLayer`, `Viewport.layerMask`; Node `Item.userLayer`, `View.userLayer`, a viewport's `layerMask`; LuaJIT `Item:user_layer`, `View:user_layer`, a viewport's `layer_mask`; Rust `Item::user_layer`, `View::user_layer`, `Viewport::layer_mask` (0 is every layer; in the browser too). A layer past 31 is refused. Rust's `Viewport` gains a field, so a struct literal names it.
- The closest points against a triangle mesh, in Rust, the C ABI, the web build, Python and every wrapper (C#, Go, Java, Node, Rust, Swift, LuaJIT, Godot, C++). `TriangleMesh(positions, indices)` holds a mesh of triangles and builds its search tree once; `Solid.triangle_mesh(tolerance)` gives a body's own tessellation as one, and `vertex_count`, `triangle_count` and `bounds` describe it. `TriangleMesh.closest_point(p, max_distance)` answers the nearest point of the mesh: the distance, the point, the triangle, the barycentric weights on its corners, whether it lies on a face, an edge or a vertex, and the vertex indices of that edge or vertex. `TriangleMesh.curve_closest_points(curve, max_distance)` answers the nearest pair of a curve and a mesh: the distance, the curve's parameter and point, the mesh point with the same fields, and a `crossing` flag where the curve passes through a triangle (distance 0). `NurbsCurve.closest_object(items, max_distance, tolerance)` now takes meshes among its items. Both queries are exact, with no tolerance; beyond `max_distance` the call answers none, and equal distances go to the lower triangle. Triangles only, no quads.
- `python fetch.py --flavour kernel-reader|kernel|reader` fetches a smaller flavour of the library (`full` by default); `fetch.py` first clears the libraries an earlier fetch left in `lib/`, so one flavour is there at a time.
- Drawing sheets for building documents (`bim.sheet`): plans, sections, elevations and schedules placed at a scale on ISO or ANSI paper under a fixed title block, cropped and titled, with warnings for a viewport off the frame, over the title block or whose view is gone; written as SVG and PDF by the C ABI (`cadaclysm_bim_sheet_svg`, `cadaclysm_bim_sheet_pdf`, `cadaclysm_bim_sheets_pdf`), Python (`Document.sheet_svg`, `sheet_pdf`, `sheets_pdf`) and the web build -- a set of sheets as one PDF, a page and a bookmark a sheet; cameras (`bim.camera`) and 3D viewports, drawn from a PNG the caller passes or as a "not rendered" box, with images in the SVG and PDF. The project gains its title block's name, number, client, address and author, and a schedule's table text now comes from the kernel, so the Schedules tab, its CSV and a printed sheet agree.
- The BIM editor's Sheets tab: a sheet's paper as it prints, panned and zoomed; New sheet; plans, sections, elevations and schedules placed by a click and moved by click-then-click; a viewport's scale, title and crop (to the plan view) in Properties; warnings outlined on the paper; Download SVG, Download PDF and a set of sheets as one PDF in number order. The project tree lists the sheets and their views, the Project fold holds the title block's fields. Save camera keeps the 3D view as a camera, which a sheet shows as a picture; the sample house comes with sheets A-101 and A-201, a 3D view on A-201.

### Changed

- The EULA names the cadaclysm library by its flavours -- `cadaclysm`, `cadaclysm_kernel_reader`, `cadaclysm_kernel` and `cadaclysm_reader` -- as well as `cadaclysm_capi` and `cadaclysm_blacksmith`, the names earlier releases ship it under. What it grants is unchanged.
- One web package: each release carries `cadaclysm-<version>-web.zip`, every WebAssembly build in one zip (`pkg/` with the readers, the kernel and the View; `pkg-reader-viewer/`, `pkg-kernel/`, `pkg-reader/` and `pkg-viewer/` for pages that load less, and `schemas/`), in place of `cadaclysm-<version>-web-reader.zip` and `-web-pro.zip`. Every web license covers all of it. `python fetch.py --web` takes no package name any more (`--web pro` and `--web reader` still fetch the latest package, with a note) and `--web <tag>` fetches a given release's; update your SDK checkout (`git pull`) for it, since an older `fetch.py` looks for the two old zips.
- The Unreal plugin binds the library's reader flavour, `cadaclysm_reader` (`cadaclysm_reader.dll`, `libcadaclysm_reader.so` on Linux and Android), in place of `cadaclysm_capi`; `build-rust.ps1` builds and stages it and removes the old files.
- The Unity package binds the library's reader flavour, `cadaclysm_reader` (`cadaclysm_reader.dll`, `libcadaclysm_reader.so`), in place of `cadaclysm_capi`; copy the reader flavour's files into `Runtime/Plugins/`, and delete any `cadaclysm_capi.dll` / `libcadaclysm_capi.so` (and its `.meta`) an earlier version left there, or every player build carries it.
- iOS: `scripts/build-render-metal-xcframework.sh` builds `CadaclysmCapi.xcframework` from the library's reader flavour (`cadaclysm_reader`); the framework's name, and the Swift package that links it, are unchanged.
- The Unreal plugin, the Unity package and the iOS XCFramework open OpenSCAD files as exact B-reps (faces), not meshes, as every flavour of the library does; code that expected meshlets from a `.scad` gets faces.
- One library, any flavour, in every wrapper. Python, Node, Java, LuaJIT, Rust (and through it Godot) and C# load one file for both the reader and the kernel: `cadaclysm` (the full flavour), `cadaclysm_kernel_reader`, `cadaclysm_kernel` or `cadaclysm_reader`, then the separate `cadaclysm_capi` and `cadaclysm_blacksmith` of earlier releases, which keep working unchanged. The kernel reads `CADACLYSM_LIBRARY` when `CADACLYSM_BLACKSMITH_LIBRARY` is not set. A call the loaded flavour leaves out fails when it is made, naming the flavour and its features (`not in this library's flavour ('kernel', features ...); the full flavour has it`), and a module whose half the flavour lacks is refused when it loads. Go, Swift and C++ link the full flavour by default: Go's `cadaclysm_reader` build tag, Swift's and CMake's `CADACLYSM_FLAVOUR=reader` link the reader flavour, and `cadaclysm_separate` / `CADACLYSM_FLAVOUR=separate` the two separate libraries; CMake's `CADACLYSM_FLAVOUR` also takes `kernel-reader` and `kernel`, which Go and Swift do not link yet. Every wrapper but Godot gains `flavour()` and `features()` on both modules: `"full"`, `"kernel-reader"`, `"kernel"` or `"reader"` and its comma-separated features, or `"reader"` / `"kernel"` and no features on the separate libraries.
- One library in every release archive. Each platform has four archives, one per flavour of the library, and every license covers all four: `cadaclysm-<version>-<platform>` is the full flavour, `cadaclysm` (`cadaclysm.dll`, `libcadaclysm.so`, `libcadaclysm.dylib`): the kernel, every reader and every writer; `-kernel-reader` is `cadaclysm_kernel_reader`, without the kernel's B-rep writers (STEP, SAT, .brep and Rhino 3dm), its IFC export and the parts catalogues; `-kernel` is `cadaclysm_kernel`, the kernel and the Document with no file formats; `-reader` is `cadaclysm_reader`, the readers, the mesher and the mesh exports. Each also carries `cadaclysm_view`, `cadaclysm_terminal` and every header, `cadaclysm_flavour.h` among them, its `BUILD` names the flavour, and its CMake package defaults to that flavour (`find_package(cadaclysm)` on the reader archive links `cadaclysm_reader`; the kernel archive gives `cadaclysm::blacksmith` and no reader). On Windows the import library ships as `<name>.lib`.
- The pip wheel, the NuGet package, the Godot addon, the Blender add-on and the Rust crate's download carry the full flavour, `cadaclysm`, with the two view libraries. Another flavour is used by pointing `CADACLYSM_LIBRARY` at it. The Godot addon's `.gdextension` names one library per platform.
- C++, Go and Swift's view loader (`view_loader.h`) finds the view library beside whichever flavour of the library the program loaded, as Rust's view libraries already did.
- SDK checkouts: run `git pull` in your checkout of the SDK before fetching 0.14.2 or later. An older `fetch.py` still downloads the full archive, but the older wrappers beside it look for `cadaclysm_capi` and `cadaclysm_blacksmith`, which no longer ship (or load stale copies an earlier fetch left in `lib/`); the new `fetch.py` clears those first.

### Fixed

- The mesher closes a sliver face thinner than the tolerance whose two long edges cross along it -- a twisted ribbon, as Rhino's tween loft leaves between two spans. Read from 3DM it was refused, and from STEP it lost triangles; either way the solid was left open along the sliver, where it now meshes watertight.
- 3DM: an extrusion with a mitred end is cut by the mitre's plane. It stopped square at the end of its path, so every mitred extrusion read the wrong shape near that end, while the SAT and STEP Rhino writes of the same solid read right.
- A sphere split into two hemispheres along its seam reads as its two halves. Both faces read as the same hemisphere, so the nearest point of the ball to a point just off it could be the great circle, far away.
- `merge_flush` merges the pieces of a read face whose file collapsed an edge shorter than the tolerance into a vertex: their trims meet where the file says they do, though their curves stop that edge's length apart, so the two pieces become one face.
- The mesher no longer asks a knot for a turn on a chord too short for the coordinates to resolve, and judges a short fill over its ring's distinct points: lofts with near-coincident sections that it refused now mesh.

- An offscreen view's `pick` and `snap` answer on a slow renderer too: its draw now waits (at most 10 seconds) for a pick or snap asked before it, so the answer is there after that one draw. On a machine with no GPU, where the view renders in software, a fresh view's first pick could take longer than the wrappers' wait and fail with "the answer never landed".
- Windows: the View's own window opens from any thread. It failed with "OleInitialize failed! Result was: `RPC_E_CHANGED_MODE`" on a thread in COM's multithreaded apartment -- the main thread of a .NET, Java or Go console app, so C#, Java and Go programs needed `[STAThread]` or a thread of their own. The window takes no drops, and now asks Windows for none.

### Removed

- `cadaclysm_capi` and `cadaclysm_blacksmith` no longer ship: the archives, the wheel, NuGet, Godot and the Rust crate carry the single library instead. Every wrapper still loads them, for programs built against an earlier release.

## [0.14.0] - 2026-11-10

### Highlights

- **One name for what draws:** `View` in every language -- the web package's `Viewer` and C#'s `Cadaclysm.Viewer` are renamed -- and Rust's `view::View` draws in the browser too, so the same drawing code runs on the desktop and in a page.
- **Snapping and materials in the View:** the point under the cursor snaps to vertices, midpoints, centres and more, for measuring and placing (View 1.22); a solid shows in a material and an opacity, whole or a subset of its faces (1.21); hidden lines take their own dash, gap, dim and colour (1.20).
- **Surface quality:** curves and NURBS faces faired to the smoothest shape within a tolerance, with inflection, continuity and curvature checks a test can fail on.
- **Symmetric bodies:** `Solid.mirror_join` builds a whole car, hull or bottle from one half, the seam squared so the halves meet smoothly.
- **A fillet's radius along a law:** `Solid.fillet_law` rounds a chain of spline creases with a radius that changes along it.
- **Closest points** from a point to a body, face, edge or curve, and between two curves.
- **OpenSCAD files read as exact B-reps** where the kernel is linked, not only as meshes.
- **BIM editor:** stairs, elevations and dimensions.
- **Documents that compute:** parameters hold text, booleans, lists and records, and expressions index them, sum them and check them; the document format is described on its own page.
- **Sketch profiles in the public kernel:** polylines, arcs, ellipses, loops and their Béziers, the web forge's own curve helpers.
- **CAM corner relief** (dog-bones at inside corners) and **a document evaluation that reports its progress**.

### Added

- Web: every package folder with the View now carries the modules the site's own apps draw with, each with typings: `viewer-host.js` (`createViewerHost`, a View in a Web Worker) and `viewer-client.js` (`attachViewer`, the page's side of it), `view-activation.js` (tap to turn a view on in a scrolling page), `view-canvas.js` (`drawingRatio`, `drawingSide`, a canvas sized to the View's drawing) and `view-show.js` (`paletteColour`, `segmentsOf`, `boxOfPoints`, `sphereOf`, `keeps`: part colours, outlines as segments, framing and when to keep the camera).
- The closest points from a curve, in Rust, the C ABI, the web build, Python and every wrapper (C#, Go, Java, Node, Rust, Swift, LuaJIT, Godot, C++). `NurbsCurve.closest_points(other, max_distance)` answers the nearest pair of two curves: the distance, both parameters and both points; a crossing answers 0. `Solid.curve_closest_points(curve, max_distance, tolerance)` answers the nearest pair of a curve and a body's boundary: the foot on the body with its face, edge or vertex, the `uv`, the normal, `refined` and a `crossing` flag where the curve meets the boundary; `Projector.curve_closest_points` does it on a prepared body for many curves. `NurbsCurve.closest_object(items, max_distance, tolerance)` answers the nearest of a mix of solids, prepared `Projector`s, curves and bare points. `NurbsCurve.closest_point` gains the same `max_distance`: beyond it the call answers none, and callers that pass none are unchanged. Curve against curve is exact; against a body it is exact when `refined` is true, else within `[d - 2/3 tolerance, d + tolerance]`.
- CAM corner relief: `MachineOptions::corner_relief` (C `cadaclysm_blacksmith_job_machine_relieved`, and a `corner_relief` choice on `machine` in Python and every other wrapper) cuts a dog-bone at every inside corner the smallest end mill leaves, notching both walls so a square mate fits, and reports each as a `relief` item. The Mill has a checkbox for it: the example plate then machines with nothing left uncut.
- Fairing a surface, and surface quality numbers a test can fail on. `Solid.faired(tolerance, degree, controls, keep, no_inflection, face)` gives a NURBS face as the smoothest sheet within the tolerance of it: least squares plus its third derivatives squared -- what a zebra's ripple costs -- weighed as heavily as the tolerance allows, so a roof lofted through traced sections comes back calm between them. It fairs on the face's own net (degree 3 to 7) or a coarser uniform one (`controls`); each side keeps its position, tangent plane or curvature (`keep`, so a `matched` G2 join survives) or moves freely; `no_inflection` holds the isocurves along u and/or v from turning over, and is refused with the nearest distance found where no fair within the tolerance can. `sheet_error` is the largest distance between the two surfaces. The numbers: `Solid.curvature_turns(face, samples)` (how many separate areas of each sign the Gaussian and mean curvature take, and the points between, as a `CurvatureTurns`) and `Solid.highlight_kink(edge, samples)` (the worst kink of the highlight lines crossing an edge, every straight light tube tried, as a `HighlightKink` -- beside `edge_continuity`). Kernel (`cadaclysm::nurbs::fair_surface`, `cadaclysm_blacksmith::fairing`), C ABI (`cadaclysm_blacksmith_surface_faired`, `_curvature_turns`, `_curvature_turn_points`, `_highlight_kink`), Python (native and in the browser), the kernel's wasm module and every wrapper (C#, Go, Java, Node, Rust, Swift, LuaJIT, C++ and Godot).
- View 1.20: cadaclysm_view_set_occluded_style and _occluded_style -- the dash, gap, dim and an optional colour of every dashed item's hidden lines and points, in every wrapper and the web package.
- What a page that draws and edits a solid reads off it, in the C ABI, the web build, Python and every wrapper: each face's round radius and chamfer distance (`Solid.face_round_radius`, `face_chamfer_distance`, 0 where none), the edges and the isocurves as rational cubic Béziers (`Solid.edge_beziers`, `isocurve_beziers`: sixteen numbers a Bézier, `x y z w` per control point), and several solids written as one STL (binary or ASCII), OBJ, glTF or GLB file's bytes (`mesh_file`, with names, a metallic-roughness material each and a tolerance; the C entry is in the `write-meshes` feature: the full and kernel-reader libraries).
- Web: `View.showSolid` takes `material`, `opacity` and `faces` (a subset of the solid's faces shown alone, with no edges), and numbers the item's faces as the solid numbers them in `pick` and `setFaceColours`, on WebGPU and on the WebGL2 triangles, subset or not.
- View ABI 1.21: `cadaclysm_view_show_solid_faces` and `CADACLYSM_VIEW_MATERIAL_*` show a kernel solid in a material (default, plastic, metal, matte, paint, brushed, glass), an opacity, and all its faces or only some, alone with no edges (a trim's ghost); a shown solid's faces are numbered as the solid numbers them in picks and `set_face_colours`. Every view wrapper's `show_solid` takes them -- Python `material=`/`opacity=`/`faces=`, Node's options, C++ `SolidOptions`, C# and Java arguments, Go `SolidOptions`, Rust `show_solid_with`, Swift `material:`/`opacity:`/`faces:`, LuaJIT's opts table -- and the wrappers now need view ABI 1.20.
- A document evaluation that reports its progress. `Document.evaluate_with(progress, cheap_only)` gives the same statuses as `evaluate`, and calls `progress(node, phase, done, total)` for every kernel step: `node` is the id of the node being built, and every heavy node reports `start` before it runs. A progress bar can show what is building, and a host whose process dies can leave that node out the next time it loads the document. C ABI (`cadaclysm_blacksmith_document_evaluate_with`, with the `CadaclysmBlacksmithDocumentProgress` callback), the kernel's wasm module (the callback a JavaScript function), Python (native and in the browser) and every wrapper with a document (C#, Go, Java, Node, Rust, Swift, LuaJIT, C++). The web forge now evaluates through it.
- View 1.22: snapping -- the point under the cursor, for measuring and placing. `cadaclysm_view_set_snap` chooses what a snap may land on, from eight kinds (`CADACLYSM_VIEW_SNAP_VERTEX`, `_MIDPOINT`, `_CENTRE` of a circular edge, `_QUADRANT`, `_EDGE`, `_FACE`, `_GRID` and `_PLANE`), the aperture in pixels and whether the view draws its marker; within the aperture the point kinds win by distance, so a corner beats the face it sits on. `cadaclysm_view_request_snap_in` and `_snap_result` ask and answer as a pick does (`CadaclysmViewSnap`: the kind, the world point, the item, node, face and edge, an edge's tangent, an arc's axis and radius, the distance in pixels and `clicks`), every draw lands the answer and shows the marker there, and `_clear_snap` hides it. Snapping starts off; once `set_snap` turns it on, a mouse hovering over a view in its own window (or one fed `cadaclysm_view_input`) snaps, the marker following it, and a click snaps as well as picks, its answer with `clicks` 1 (2 for a double click). `_set_work_plane` and `_clear_work_plane` move the grid and plane snaps onto any plane, with its own spacing. Python, C++ (`view.hpp`, `view_loader.h`), C#, Go, Java, LuaJIT, Node, Rust and Swift bind it (`set_snap`, `snap`, `last_snap`, `clear_snap`, `set_work_plane`, each in its language's idiom), as does the web View (`setSnap`, `snap`, `clearSnap`, `setWorkPlane`). Python's "no argument is all, None is off" carries over where the language can: Node `null` is off; C# and Java a null array is off; Rust `set_snap(&[])` is off and `SnapKind::ALL` is all; LuaJIT `false` is off, as `nil` cannot be both; C++ `std::nullopt` is off and the default is `{"all"}`; Go `SetSnap(0, ...)` is off and `SnapAll` is all; Swift `nil` or an empty set is off and the default is every `SnapKind`. Every view wrapper now needs view ABI 1.22. The render view and terminal libraries refuse snapping by name.
- `Solid.mirror_join(plane, snap, tolerance)`: a symmetric body from one half -- half a car, a hull or a bottle modelled once -- in the kernel, the C ABI (`cadaclysm_blacksmith_mirror_join`), the web build, Python and every wrapper. The half and its reflection across the plane are sewn into one body, the half's faces first. With `snap` above 0, every NURBS face that is its whole surface and has a side within `snap` of the plane is squared to it first: that side pulled onto the plane and the next row of control points stood straight off it along the plane's normal, so the surface crosses the plane at 90 degrees and meets its mirror tangent and curvature continuous, with nothing past that row moved; faces side by side along the plane are squared alike and sew back. A `SymmetryReport` gives the seam edges, the faces squared and the furthest move, the seam's worst gap, angle and curvature jump -- the largest difference of normal curvature in any direction, which on a mirror seam is the twist along it, since the curvature square to it always matches -- and the naked edges left. Refused by name: a half on both sides of the plane, no edge on it, and a face whose next row lies on the plane or past it.
- Sketch curves as profiles, and a profile's Béziers for drawing. `Profile.polyline(points, closed)`, `Profile.arc(centre, r, a0, a1)` (equal angles: the whole circle), `Profile.arc_through(start, through, end)` and `Profile.ellipse(centre, rx, ry)` build the shapes a sketch draws, lines and arcs exact. `profile.beziers(frame)` hands any profile back as rational cubic Béziers, sixteen numbers each, on the sketch plane or carried onto a frame, and `Profile.from_beziers(beziers, recognise)` reads them back, with lines and arcs recognised or every Bézier kept exact. `Profile.loops(pieces, tolerance)` finds the closed loops among open curves the way a CAD sketch does (ends meeting two at a corner). `Profile.chain_order(pieces, tolerance)` gives the order and turn of each piece `Profile.chain` used. C ABI (`cadaclysm_blacksmith_profile_polyline`, `_arc`, `_arc_through`, `_ellipse`, `_from_beziers`, `_bezier_count`, `_beziers`, `_loops`, `_chain_order`), the kernel's wasm module, Python (native and in the browser) and every wrapper (C#, Go, Java, Node, Rust, Swift, LuaJIT, Godot, C++). These are the web forge's own curve helpers, now in the public kernel.
- The closest point of a body, a face, an edge or a curve to a point, in Rust, the C ABI, the web build, Python and every wrapper (C#, Go, Java, Node, Rust, Swift, LuaJIT, Godot, C++). `Solid.closest_point(p, max_distance, tolerance)` answers the nearest point of a body's boundary: the distance, the foot, the face, edge or vertex it lies on (with its index and, for an edge, the fillet-table index), the `uv` when it lies inside a face, the normal (the face's outward normal; at an edge or a vertex, the direction from the foot to the point) and `refined`, which says whether it is the exact minimum or the mesh's, within `[d - 2/3 tolerance, d + tolerance]`. Beyond `max_distance` it answers none. `Solid.projector(tolerance)` builds the search once for many points. `Solid.face_closest_point(face, p)` and `Solid.edge_closest_point(edge, p)` answer on one trimmed face or one edge, exactly, and `NurbsCurve.closest_point(p)` gives a curve's nearest parameter and point with a `unique` flag where the answer is a pick among equals. Checked against closed forms and a dense sample of each body.
- Fairing a curve, and curvature checks a test can fail on. `NurbsCurve.fair(points, degree, tolerance, no_inflection)` gives the smoothest curve of degree 3 to 7 within the tolerance of every point, through the first and the last: least squares plus the squared derivative of curvature, weighed as heavily as the tolerance allows, so a design line traced off a drawing comes back with a calm comb where `fit` follows the tracing's wobble. `NurbsCurve.faired` does the same from a curve. `no_inflection` holds the curvature to one side over the whole curve or a span of it, and is refused, with the nearest distance found, when no curve within the tolerance can keep it. The checks: `NurbsCurve.inflections` (where the comb flips side), `NurbsCurve.knot_continuity` (the largest tangent turn and curvature jump at the knots, with where each is) and `Solid.edge_continuity(edge, samples)` (the worst gap, normal angle and curvature difference between the two faces of any edge of a body, of any surface kind, as a `Continuity`). Kernel (`cadaclysm::nurbs::fair`, `inflections`, `curve_continuity`), C ABI (`cadaclysm_blacksmith_nurbs_curve_fair`, `_faired`, `_inflections`, `_knot_continuity`, `cadaclysm_blacksmith_edge_continuity`), Python (native and in the browser), the kernel's wasm module and every wrapper (C#, Go, Java, Node, Rust, Swift, LuaJIT, C++ and Godot, with a `KnotContinuity` record each).
- Stairs in the BIM editor. A stair follows a walk line of straight segments and arcs at a width, so one rule lays out straight, L and U flights, landings or winders at each corner, curved flights and spirals. It takes the fewest risers that keep each one under its type's largest, from its level to the next one up, so moving a level re-steps it; the going is fixed, so the steps set the last segment's length. Stairs cut the floors they rise through wherever they need headroom. Plans draw them with a break line, the part above dashed, an arrow and UP, and show the part seen through the opening on the level above with DN. Sections cut and fill them, their rails come with them, and the IFC export writes each as a stair with its flights, landing slabs and railings. The Stair tool draws a path or a spiral with a live preview of the treads and the risers left; Properties switch a corner between landing and winders and bend a segment; the sample house has a U stair up from the kitchen. The kinds (`bim.stair`, `bim.stair_type`, `bim.stair_body`) are ordinary document nodes, so the C ABI and Python add and read them.
- Dimensions in the BIM editor. A dimension names references on elements -- a wall's faces, centre and ends, an opening's centre, jambs, sill and head, a column's faces or a round column's outline, a beam's sides, a floor's edges, top and underside, a level's line, a roof's eave and ridge, a stair's walk line -- and follows them as they move: linear chains (horizontal, vertical or aligned, with their total), angles, radii, and height marks in sections and elevations. A lost reference drops its witness and the chain re-labels; one left too short draws nothing and says why. The Dimension tool snaps to the references a plan, section or elevation offers and previews as it goes; Properties edit the references (Add point, Remove), the line drags, the project sets the unit (mm, cm, m or feet and inches), decimals and fraction, and the section SVG export draws them. `bim.dimension` is an ordinary node, so the C ABI and Python add it and read its texts; `cadaclysm_bim_dimension_refs` and `cadaclysm_bim_dimension_preview` give the web build the references and a layout.
- The panel verbs in every wrapper but Godot (C#, Go, Java, Node, Rust, Swift, LuaJIT, C++) and in the web build (Python under Pyodide, and Node over the wasm): `split_along_curve` and `panel_gap` on `Solid`, `offset_on_sheet` on `NurbsCurve`, in each language's spelling, with Python's defaults.
- A fillet whose radius follows a law along a chain of spline edges. `Solid.fillet_law(edges, [(share, radius), ...])` rounds a tangent chain of creases between NURBS faces -- a car's shoulder line drawn across several patches -- with the radius given at stations along the chain (each a share of its arc length, 0 to 1) and run through smoothly by a monotone cubic, so it never swings past its stations: `[(0, 4), (1, 12)]` grows from 4 at one end to 12 at the other. Where the faces either side change from one edge to the next across smooth seams, the fillets meet on one shared end. `fillet` with one radius now rounds such a chain too, where it refused the vertex between as a corner. Kernel (`fillet_law`), C ABI (`cadaclysm_blacksmith_fillet_law`), Python (native and in the browser), the kernel's wasm module and every wrapper (C#, Go, Java, Node, Rust, Swift, LuaJIT, C++ and Godot).
- OpenSCAD files read as exact B-reps where the kernel is linked: primitives with the `$fn` rule, transforms, booleans, coloured regions, 2D shapes and extrusions build kernel solids, polyhedra become planar solids and anything else falls back to facets. `Solid.open("part.scad")` hands over the body like any other CAD file, and it writes to STEP.
- Elevations in the BIM editor: Add elevations places North, South, East and West round the building in one step, and an Elevation tool places more. An elevation shows what lies beyond its line with hidden lines removed and nothing cut, the building's outline drawn heavier and a ground line along the lowest level; it opens, selects and moves levels as a section does, and downloads as SVG (ground 0.7 mm, outline 0.5 mm).
- Dimensions in the BIM editor (`bim.dimension`): linear, aligned, angular, radial and height dimensions laid out on plans, sections and elevations, each view drawing only those whose references it draws; an under-counted dimension warns instead of failing its view, and Python reads a dimension's texts.
- Documents hold more than numbers. A parameter is a number, a quantity, an expression, a boolean, text, a list or a record (`{"M4": 4.5, "M5": 5.5}`), nested. Expressions work on all of them: text in quotes, joined with `+` and written from a number by `text(x)`; record literals; `x[i]` (from 0, negative from the end) and `x['k']`; `sum`, `min` and `max` of a list, `column(rows, i)`, `range`, `repeat`, `zip`, `len` and more. Text fields such as a label take an expression too. A `check` node states a condition the document must satisfy -- false fails the node with its message, naming the first failing item of a list -- so a parametric part can refuse sizes that do not fit. Errors on a list node name the item, counting from 0. The site has a new Document format page: every key of the file, parameters, nodes, expressions and their functions, lacing and checks, for reading, writing or generating a document by hand.

C ABI (`cadaclysm_blacksmith_with_material`, `_solid_material`, `_styled`, `_solid_style_location`, `_solid_style_identification`), the kernel wasm module, Python and every wrapper: C#, Java, Go, Rust, Swift, C++, Node, LuaJIT and Godot.

### Changed

- `scale` (`cadaclysm_blacksmith_scaled`, `Solid.scaled`) no longer refuses a body with a conic trim on a cylinder or cone (as STEP, IGES and 3dm readers hand them over): the trim is rewritten as the exact NURBS of its stretch. Mirroring a body whose loops keep their file's winding no longer hands a spline face its complement.
- A face reference finds its face again after a resize: where a resize moved its plane and no face of that kind passes through the remembered point any more, `find_face` (`cadaclysm_blacksmith_find_face` in C and wasm, `Solid.find_face` in Python and the other wrappers) takes the face of that kind facing the same way -- the only one, or the one clearly nearest -- within the face's own size of the point. Before, it found none (-1). A face whose surface still passes through the point is no longer taken by its nearest boundary when that boundary is farther off than the face's own size: that is -1 now. `face_ref` takes a ring face's point on the face itself, not in its hole, so a washer or a flange's face is found by its own point.
- `join_sheets` sews T-junctions: at a tolerance above zero, a naked edge with another sheet's corner lying on it -- a patch side that is a chain of curves beside a neighbour's single curve -- is first cut there, and its pieces are sewn to the edges along it (a cut exact curve stays exact, a NURBS in NURBS pieces). `JoinReport.naked_before` now counts the naked edges once those cuts are made, so `naked_before - 2 * sewn == naked_after`. In Rust the cut is `TrimmedBrep::split_free_edges_at_ends`.
- The verbs that need a manifold solid refuse a merge's non-manifold body and point to its regions (`BuildError::NonManifoldOperand`: "the join needs a manifold solid, and this one has edges of three or more faces (a merge): take its regions with region_solid"): `join`, `cut`, `common`, the splits and trims, push-pull, fillet, chamfer, `shell`, `thicken` and the mass. The STEP writer refuses such a body too ("write its regions"), per part in an assembly. A body is refused when some finite region is bounded by face sides of both senses -- a cell between two others -- so a solid with a cavity and several solids in one body are taken as before.
- The collider's broad phase for large assemblies: from 1,000 parts `Collider.check` finds the candidate pairs with an R-tree over the parts' world boxes instead of testing every pair, 3.5 times faster at 1,000 parts and 15 times at 5,000. The hits, the stats and the pairs a `share` splits are the same as before.
- An edge is closed, for the arc-length divides, when its range is its curve's whole loop, no longer when its ends lie within the length error of each other, so the answer no longer moves with the accuracy asked. An ellipse arc crossing angle 0 can now be measured and sampled. Refcheck compares closed edges from a canonical start instead of setting them aside.
- `health` and `healed` (`Brep.health`, `Brep.healed`, `Solid.health`, `Solid.healed` in every wrapper) are faster, with the same answers to the bit -- 2.6 times at the median over the healing census's bodies that took 5 s or more, up to 28 times where a body's edges stand off its faces: a surface inversion stops once its step stands still and keeps, while a face's rings are built, the searches it has run; a band round a cylinder, cone, sphere or torus is vouched for by a row integral with the surface's own area element before any full quadrature; and a heal that changes nothing reports its input's health instead of computing it again. The healing census's four largest samples (Cruise_Assembly.stp, ufi.stp, Scania-8x4.stp, audi_r8.sat), which ran out of time, now heal every body (`docs/healing-census.md` §6). The mesher and the area and mass integrals share the held inversions.
- Bodies glued along shared edges take the exact boolean route: where two operands' edges are twins (the same edge, as the halves of a split carry it), their faces abut on one surface, or they meet at shared vertices and corner slivers, the meeting is read as that instead of refused, so a sphere split into caps and joined back is now an exact union.
- The Kiln is a cage modeller only: no solid mode, booleans, fillets or shells; Export STEP converts the cage to the exact NURBS solid, and STL, OBJ and glTF write its smooth mesh. The SDK's conversion, booleans, fillets and shells are unchanged.
- Showing items into a View is cheap: a show keeps its item, and the next frame (`draw`, `image`; in the C ABI `cadaclysm_view_draw` and `cadaclysm_view_image`), pick or `renderer_mut` merges and uploads every item shown since in one go, where each show merged and uploaded every earlier item again. 400 small solids now take 0.1 s to show and draw instead of 17 s, and a car's 474 parts no longer spend ~25 s in shows before the first frame. A show is still refused at once where the items with it would not fit the device's buffers; a GPU rejecting the upload itself is now reported by that frame (`take_status`, a false `cadaclysm_view_draw` or `cadaclysm_view_image` with the reason), the items staying shown, and no longer by the show. `View::settle_shows` uploads them now, returning that failure, for a host that wants it at a point of its own; `View::export` draws what the last merge uploaded.

### Removed

- Breaking, Rust: `cadaclysm_blacksmith::BuildError::NoExactScale` and `cadaclysm_brep::NO_EXACT_UV_SCALE`, with the refusal they named (see Changed). A map's refusal is `BuildError::Transform` now, its sentence one of `cadaclysm_brep`'s constants (`SINGULAR_MAP`, `NON_FINITE_MAP`, `NO_EXACT_NURBS`, ...): match the variant, not the text.
### Fixed

- `health` reports the small holes of STEP and SAT bodies, and `healed` fills them. Their holes come in as loops of no stated kind (a STEP `FACE_BOUND`, every SAT loop), and the small-hole test took only a loop marked `Inner`. Now a loop of no stated kind is a hole beside a loop marked outer, or when another loop of its face encloses more of the surface's parameters, whatever order the file wrote them in; a loop that winds round a closed surface (a cylinder's rim) never is. `samples/pinhole-sheet.stp` and `.sat` join the `.brep`, with C ABI and Python tests.
- IGES: a surface that a trimmed or bounded surface stands on is placed by its own transformation. A boundary given only in model space was projected onto the surface as the file wrote it, unplaced, so a surface of revolution with a matrix of its own read as a fold of no area at the origin. Each of the 116 surfaces of revolution in `AssemblyExample-Assembly.iges` carries such a matrix; its first part, a cylinder, now lands in the box the assembly's STEP export gives it.
- Python kernel module: an index or count past 32 bits, negative or not whole (`2**32`, `-1`, `0.5`) is refused with the call's name instead of wrapping silently to another index (on the native and the web backend alike).
- A View filled with many items before it draws -- an offscreen view of a car's 500 parts, shown one by one and saved once -- no longer runs out of memory: every show uploads the whole scene again, and nothing handed the queue the copies those uploads wrote, so each upload's staging and the buffers it replaced were held until the first draw (9.4 GB for the car, then "the GPU rejected the uploaded scene: ... Buffer with 'line occlusion' label is invalid"). Each upload now submits its copies and frees what the device has finished with; the same car peaks at 0.3 GB.

## [0.1.0] - 2026-09-15

The first public release: CAD file readers, the B-rep mesher and the blacksmith modelling kernel behind one C ABI, with Python, C#, Go and Java wrappers, for Windows, macOS and Linux.

### Added

- STEP reader (AP203, AP214, AP242) driven by the EXPRESS schema, with the schemas built in: exact B-rep geometry (analytic surfaces, NURBS, surfaces of revolution and extrusion, trimmed curves), open shells, wireframes, colours, and the assembly graph read as a placed, instanced tree. Files in legacy encodings and UTF-16 read with their names intact.
- IFC reader (IFC2X3, IFC4, IFC4X3): products with unit scaling, faceted and advanced B-reps, extrusions and swept solids as exact surfaces, CSG and half-space clipping, openings cut from walls, parametric steel sections, the spatial hierarchy, colours and transparency, and shared shapes read once and instanced.
- SAT reader: bodies and lumps with exact trimmed faces, analytic and spline surfaces, tolerant edges, wire bodies as free curves, named attributes as node properties, and per-face names and colours.
- 3DM reader: B-reps, extrusions, SubD objects, curves, text, block instances, layers, visibility and object colours.
- IGES reader (trimmed and bounded surfaces, surfaces of revolution, space curves, colours) and OCCT .brep reader.
- OpenSCAD: the full language (functions, modules, include/use), 2D shapes and extrusions, CSG, `hull()`, `offset()`, `text()` and per-object colours; zip archives open with a member picker.
- One B-rep mesher for every format: constrained Delaunay triangulation of trimmed faces, crack-free shared edges, a quality setting, triangle caps per face and body, progress, and a report of faces that could not be meshed.
- Edges, curves and surface isocurves for every format, as polylines or as exact rational Bezier segments; faces can also be handed over as trimmed Bezier patches for drawing on the GPU without meshing.
- Levels of detail, meshlets with a crack-free simplification hierarchy, oriented boxes, primitive fitting, convex hulls, collision bodies and signed distance fields.
- A query language (`cadaclysm_query`) that selects nodes by name, property and containment.
- The C ABI: open from file or memory with one options struct, an assembly tree with typed attributes, lazy per-part meshing, placements and instancing, diagnostics, cancellation, format lists for file dialogs, mesh export, and axis conventions (Y-up, Z-up, custom).
- The blacksmith modelling kernel (`cadaclysm_blacksmith`): exact primitives, sketches with lines, arcs and splines, extrude, revolve, sweep and loft, drafted extrusions, exact booleans (join, cut, common), fillets, chamfers and shells, face and edge selectors, sheet operations, meshing and STEP export (AP203).
- Wrappers: Python (reader and kernel), C#, Go and Java (JDK 22+, FFM API).
- Licensing: license file lookup and offline verification, with license info and build date calls in the C API and the wrappers.
